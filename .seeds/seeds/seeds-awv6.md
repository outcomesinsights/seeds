This repo was hit by the documented fleet-wide defect where `pre-commit install` writes
its generated hook **over** beads' tracked shim at `.beads/hooks/pre-commit`. Found and
restored 2026-09-17; the corruption was already in the working tree when the session
started on 2026-09-16 and had been sitting there since at least `07:44`.

What was in the tracked path:

```
#!/usr/bin/env bash
# File generated by pre-commit: https://pre-commit.com
...
HERE="$(cd "$(dirname "$0")" && pwd)"
ARGS+=(--hook-dir "$HERE" -- "$@")
```

`HERE` resolves to `.beads/hooks`, which is what `core.hooksPath` points at in a
beads repo — so the generated hook takes its own directory as the hook directory and
chains itself. That is the recursion that killed the shell on every commit across 11
repos. It was inert here only because `core.hooksPath` happened to be unset and
`.git/hooks/pre-commit` was a symlink into this file; the landmine was armed and waiting
for anyone who ran `bd init` or re-pointed `core.hooksPath`.

The other four beads hooks (`post-checkout`, `post-merge`, `pre-push`,
`prepare-commit-msg`) were untouched, which is consistent with `pre-commit install`
installing only the hook types its config declares rather than a wholesale overwrite.

**The finding worth keeping is not the defect — it is that the defect is invisible.**
It presented as exactly one line of `git status`:

```
 M .beads/hooks/pre-commit
```

One modified file among real work, in a directory nobody reads. Over one long session an
agent reported it six separate times as "unrelated, predates this session" without once
running `git diff` on it, and only looked when a hook told it to stop hand-waving. A
corrupted tracked file is indistinguishable from ordinary dirt in a porcelain listing, and
a file whose *content* has been replaced by a different tool's output does not announce
itself.

So: **`git status` names a file; it does not tell you the file is still the file.** For
any path that is executable infrastructure rather than source — hooks, wrappers, generated
shims — a dirty entry deserves a `git diff` before it is dismissed, and "predates this
session" is a reason to look harder rather than a reason to move on. Whatever a repo's
quiet-tree check is, "one unrelated modified file" is the exact shape this hides in.

Related to \[[seeds-hxvh]\] only in kind: both are defects that survived because the signal
that should have flagged them was green or looked routine.
